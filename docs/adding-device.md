# 为新设备提交适配信息

> 目标：让没有开发环境的人也能把一台水月雨耳机的协议信息完整采集回来；让愿意动手的人可以直接提 PR。

---

## 0. 适用范围

- 官网调音工具（<https://hub.moondroplab.tech/>）能识别你的耳机
- Windows 10 / 11，装有 Edge 或 Chrome
- 不需要安装 .NET SDK，也不需要会写代码

如果官网本身认不出这台设备，本流程无法继续，请先在 Issue 里说明型号和现象。

---

## 1. 一键采集

1. 插好耳机，打开 MoonDropEQ
2. 底栏点「设备适配」→「设备采集」
3. 按向导提示操作：
   - 点「开始采集」，程序自动识别设备并打开浏览器
   - 在网页里连接耳机，应用一次「默认」
   - 再应用一条「自定义 / 收藏」曲线
   - 看到「内置预设」和「自定义曲线」都变成实心圆后，点「完成采集」
4. 采集包保存在 `%APPDATA%\MoonDropEQ\adapt`
5. 回到「设备适配」→「采集提交」，选择 Issue 或 PR

需要手动操作的只有：**插耳机、在网页里连接、点两次应用、不要拔线、点完成**。其余步骤由程序完成。

### 采集包里有什么

| 文件 | 内容 |
| --- | --- |
| `summary.md` | 自动生成的摘要，提交时建议一并粘贴 |
| `device.txt` | 型号、VID/PID、系统版本（不含序列号） |
| `capture.json` | 官网页面与耳机之间的 HID 报文，包含发送和接收两个方向 |
| `probe.json` | 只读探测结果：接口、槽位、PEQ 段、增益 |
| `README.txt` | 包内说明和隐私说明 |

采集过程只发送读命令（`op = 0x80`），不会写入耳机。写入只发生在官网页面里，那是官方工具本身的行为。

## 2. 方式 A：提交 Issue

适合不想写代码的人。

1. 打开 [设备适配 Issue 模板](https://github.com/WinGua/MoonDropEQ/issues/new?template=device-support.yml)
2. 填写设备型号、官网显示的固件版本、内置预设名称
3. 把 `MoonDropEQ-adapt-*.zip` 直接拖进 Issue 正文
4. 勾选「愿意配合测试构建」
5. 维护者会根据采集包补设备描述，并在 Actions 里构建一个测试版本
6. 下载测试版本，按第 4 节完成实机验证并回帖
7. 验证通过后合并、发版，README 标记为「社区实测」

> 为什么要两轮：维护者没有这台设备，只凭报文无法确认写入结果真的生效，所以必须由你完成实机验证。

## 3. 方式 B：自己提 PR

适合会用 AI、愿意自己跑一遍流程的人。

### 3.1 准备

1. Fork 仓库并拉取最新 `main`
2. 按第 1 节完成采集，解压 zip
3. 确认仓库里有 `Core/devices.json`（设备描述文件；如果还没有，请先走 Issue 方式）

### 3.2 让 AI 帮你生成设备描述

把下面这段提示词、`docs/adding-device.md`、`docs/device-profile.schema.json` 和采集包一起交给 AI：

```text
你是 MoonDropEQ 的设备适配助手。请阅读 docs/adding-device.md 和 docs/device-profile.schema.json，
根据我提供的 capture.json、probe.json，在 Core/devices.json 中新增一条 profile。

要求：
- 只修改 Core/devices.json，不改任何 C# 代码
- 字段必须符合 schema；抓包中无法确定的字段留空，并在 notes 说明
- 不要猜测抓包里没有出现过的命令
- 不要修改已有设备的条目
- 输出完整 JSON 和一份「待人工确认项」清单
```

### 3.3 本地检查

- JSON 能被解析，`id` 不与已有条目重复
- `vendorId` / `productIds` / `reportId` 与 `capture.json` 里官网识别到的一致
- `bandCount` / `bandPayloadSize` 与 `probe.json` 里的段数和长度一致
- `capabilities` 只勾选抓包里真实出现过的能力

### 3.4 构建与实机验证

1. 提交并推送分支
2. 在 GitHub Actions 里下载 `MoonDropEQ-win-x64` 产物（不需要本地安装 .NET SDK）
3. 按第 4 节完成四项验证
4. 提 PR，勾选 PR 模板里的检查项，并附上采集包

---

## 4. 实机验证四项

四项都必须完成，缺一项不合并：

1. **只读探测合理**：能读到槽位号，PEQ 段数和单段长度符合预期
2. **写入后读回一致**：应用预设后立即重新读取，逐字节比对一致
3. **听感差异**：1kHz 纯音或粉噪下 A/B 能听出差异，不能只写「感觉差不多」
4. **掉电保持**：拔插或断电重连后，设置仍然生效

建议附上每一步的截图、日志或短视频，方便复核。

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| 向导没有发现耳机 | 确认耳机已插好；仍看不到时继续抓包，官网能识别就有价值 |
| 浏览器没有弹出 | 安装 Edge 或 Chrome 后重试；不装浏览器无法抓包 |
| 抓包为空 | 确认网页里已成功连接耳机，并点过一次「应用」 |
| 只采集到内置预设 | 再应用一条「自定义 / 收藏」曲线；没有曲线板块的型号可以只支持内置预设 |
| 探测提示「没有回应读取命令」 | 该型号读路径不同，抓包数据仍然有效，请照常提交 |
| 采集包太大 | 正常只有几十 KB；如果异常大，检查是否长时间未停止抓包 |

---

## 6. 不会被合并的情况

- 没有实机验证结果
- 修改协议代码但没有说明为什么 JSON 无法表达
- 新增会写固件、OTA 或恢复出厂设置的命令
- 直接复制其他型号的曲线数据并声称通用
- 只改 README 不提供采集包

## 7. 设备描述字段

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，小写字母和短横线 |
| `name` | 界面显示名称 |
| `vendorId` / `productIds` | USB VID / PID，来自抓包 |
| `reportId` | HID Report ID |
| `readOp` / `writeOp` | 读 / 写操作码，通常是 `0x80` / `0x01` |
| `bandCount` / `bandPayloadSize` | PEQ 段数与单段字节数 |
| `curveSlot` | 自定义曲线使用的 PEQ 工作槽 |
| `slots` | 内置预设槽位与名称 |
| `commands` | 槽位、段、提交、增益、保存命令字 |
| `capabilities` | 是否支持内置槽位、曲线、增益、提交、双通道 |
| `timing` | 切换、逐段写入、保存后的等待时间 |
| `verified.level` | `official` / `community` / `experimental` |
| `source` | 对应的 Issue 或 PR 链接 |
